# Documentation

## Making diagrams

- **[What the research says about diagrams](state-of-the-art-diagrams.md)** —
  the state of the art: Moody, Purchase, Petre, the meta-analysis on spatial
  contiguity, the C4 model. And why that literature settles the question of
  integrating with draw.io.
  ([laid-out version](state-of-the-art-diagrams.html))
- **[Making a diagram that reads](shapes-colors-arrows.html)** — the practical
  guide: which shape for which use, the colour rules, arrows, spacing, and the
  greyscale test.
- **[Scope audit](scope-audit.md)** — does the set serve an architect, or one
  architecture? The counts, the gaps found, and what was added to close them.
- **[Our choices against the established conventions](conventions-audit.md)** —
  an audit against C4, C4-PlantUML, draw.io and AWS: what is confirmed, what we
  had to correct, and the gap that remains.
- **[Reviewing a diagram — the checklist](diagram-review-checklist.md)** — nine
  points, in the order of measured impact.
- **Dark variants** — every view has its `-dark.svg` twin, produced by
  `scripts/dark.mjs`. The symbols are not retouched there: Spring Boot's green
  is a brand colour, and inverting it would produce a false logo.
- **[Context view](example-context.svg)** — level 1 of C4, which we were
  missing: who uses the system and what it talks to. It is the only view sparse
  enough to carry the description C4 requires — name, type and description —
  without becoming unreadable.
- **[Full view](example-full.svg)** — the diagram that exercises the nine
  shapes, zone nesting, the accent, the instance identifiers and the three
  arrow-label regimes. It serves as a demonstration and as a regression test: it
  is the first view where a broken rule shows.
- **[A complete example](example-voltis.svg)** — an architecture diagram
  assembled with the badges from this repository, generated by
  `scripts/example.mjs`.
- **[A layered example](example-layers.svg)** — a marketplace in three layers,
  with the sizing of every building block.
- **[Analytics pipeline](example-analytics.svg)** — a deliberately different
  architectural style: no cluster, no long-running service, no JVM. Ingestion on
  demand, a topic, a data lake, a warehouse, a feature store and a served model.
- **Several views of one system**, at distinct levels of abstraction:
  [hardware foundation](example-infra.svg) ·
  [Kubernetes platform](example-k8s.svg) ·
  [inside one service](example-component.svg) ·
  [delivery chain](example-delivery.svg).

## Decisions

Format: [Michael Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions).

- **[0001](adr/0001-six-layer-colours.md)** — Six layer colours, imposed, rather
  than one colour per protocol
- **[0002](adr/0002-reuse-existing-logos.md)** — Reuse the official logo as soon
  as one exists and is redistributable
- **[0003](adr/0003-shape-grammar.md)** — A shape grammar, normative and closed
- **[0004](adr/0004-excalidraw-secondary-route.md)** — Keep the Excalidraw
  route, second
- **[0005](adr/0005-node-shape-and-clarifications.md)** — A ninth shape: the
  deployment node
- **[0006](adr/0006-quality-markers.md)** — Qualities are markers, not badges
- **[0007](adr/0007-fill-scale-and-accent.md)** — Widen the fill scale, and
  accent one subject per diagram
- **[0008](adr/0008-logotypes.md)** — A logotype does not write its name twice
